# v0.10.0 migration baseline

Recorded on 2026-11-08 from commit `f32551e` on `feature/avalonia-migration`, before Core extraction. The application version is 0.10.0. This is a behavior baseline, not a new release. Existing release tags are unchanged.

## Expected functionality

| Area | v0.10.0 behavior to preserve |
| --- | --- |
| Launch and input | Windows Forms on .NET 8. A valid first folder argument takes precedence over the working-directory fallback and saved folder history. Editable folder/search histories retain 10/20 entries. Browse selects a folder; Enter invokes Search/Cancel. Empty patterns and missing folders are rejected. |
| Search | External PATH-resolved `rg`; explicitly selected `rga` mode requires rga and never silently falls back. Arguments start with `--json --line-number --color never`, followed by selected context/sort flags, then `--`, pattern, folder. No shell executes these arguments. No dedicated literal/case controls exist; inline regex flags and inherited engine configuration retain their existing behavior. |
| Context and sorting | Before/After counts range from 0 to 100. Optional file sorting uses `--sort` or `--sortr` with path, modified, accessed, or created. Sorting remains the engine's responsibility, including errors for unsupported criteria. |
| Results | Match ranges come from JSON UTF-8 byte offsets converted to UTF-16 indices. Preserve multiple matches, Unicode/emoji, base64 data, invalid UTF-8 replacement, multiline records, context gaps, and empty matches. Invalid path bytes have no active navigation link. Raw NULs remain in structured data; the formatter displays them as `␀`. |
| Presentation | Black, unwrapped, selectable output; blue bold underlined filename headings, green match line numbers, gray context/separators, orange-red bold matches. Double-clicking a heading opens the original file in its default application. Zero-length matches do not color an unrelated character. |
| Counts and completion | Count matching output lines, not individual occurrences or summary statistics. In rga mode these are converted-text lines. Cancelled, limited, and failed searches retain displayed results and explicitly label incomplete counts. Exit codes 0/1 require a JSON summary for normal completion; other exits or malformed/truncated output produce failures. |
| Responsiveness | Search becomes Cancel; search inputs are disabled during execution. Closing cancels and waits for cleanup. Worker parsing, bounded channel capacity 2, batches at 128 lines / 65,536 estimated characters / 50 ms, including quiet-period flushing. Cancellation requests process-tree termination off the UI thread. |
| Limits | 10,000 result lines including context; 2,000,000 estimated characters including path/format allowance; 16,384 characters per result line; 4,194,304 characters per JSON message. Stderr capture is bounded to 16,384 characters while the pipe continues draining. |
| Menus and layout | File exports; View independently toggles search options and command preview, reclaiming space in all four combinations; Help opens Check Dependencies and About. New preferences show options and hide command. Preview updates even when hidden. |
| Exports | HTML retains highlighting and file links; Markdown retains filename links and code blocks. Both preserve order, context, and captured search metadata/status independently of later input edits. Ctrl+S opens export. No-match and incomplete reports remain exportable. |
| Preferences | `%APPDATA%\RipgrepSearch\settings.json`; histories, context counts, rga selection, sorting, and visibility persist. Missing/unreadable settings fall back to defaults; settings errors must not stop searches. |
| Dependency dialog | Background `--version` probes for rg/rga with a five-second timeout, resolved paths, Installed/Not found/Error states, Refresh, selectable paths, expandable problem details, conditional installation links, and Copy Diagnostics using the last completed results. Reports redact the current profile directory as `%USERPROFILE%`. Converters are not verified by the dialog. |
| Windows integration | Dependency refresh rebuilds this process's PATH from saved system/user registry values without changing Windows settings. Optional Explorer scripts register/unregister current-user folder/background/drive commands; launch only selects the folder. |
| Packaging | `publish-single-exe.bat` publishes self-contained win-x64 with single-file/native-library extraction. rg, rga, converters, and Explorer scripts are not bundled. |

## Existing tests and commands

The package-free Windows runner is `tests/RipgrepSearch.Tests/Program.cs`, with dependency scenarios in `DependencyTests.cs`. It references the WinForms application and targets `net8.0-windows`.

```powershell
dotnet build RipgrepSearch.csproj -c Release
.\run-tests.ps1
# Equivalent full suite:
dotnet run --project tests/RipgrepSearch.Tests/RipgrepSearch.Tests.csproj -c Release
# Existing subsets:
dotnet run --project tests/RipgrepSearch.Tests/RipgrepSearch.Tests.csproj -c Release -- --ui-only
dotnet run --project tests/RipgrepSearch.Tests/RipgrepSearch.Tests.csproj -c Release -- --dependencies-only
```

The suite covers JSON parsing/Unicode/base64/zero-length matches; real rg/rga regex, fixed-string, case-insensitive, multiline and context searches; comparison with legacy matching-line counts; all sort fields/orders; exports; malformed output; limits; quiet streaming; cancellation and descendant processes; ZIP/DOCX/PDF documents; dependency statuses/timeouts/PATH refresh; offscreen WinForms rendering, visibility combinations, focus, and diagnostic copying. Tests use isolated fixtures/settings under build output; they do not install tools or change saved Windows environment settings. Full tests require rg, rga, pandoc, and pdftotext. They are a regression suite, not comprehensive startup/memory benchmarks or native UI acceptance tests.

## Initial Core extraction validation

Only `SearchResults.cs`, `RipgrepJsonParser.cs`, and `SearchRunner.cs` moved into `src/RipgrepSearch.Core`. Their contents match the baseline Git blobs exactly. Core targets `net8.0;net10.0`, with no packages or UI references; existing internal types and the `RipgrepSearch` namespace are retained through friend-assembly access for the application and test runners. The application stays `net8.0-windows`, references Core, and excludes `src/**/*.cs` alongside its existing test-source exclusion. Existing tests are unchanged. No search behavior, application version, packaging script, or release tag was intentionally changed.

With the .NET 10 SDK installed, normal validation commands are:

```powershell
dotnet build RipgrepSearch.csproj -c Release
dotnet run --project tests/RipgrepSearch.Tests/RipgrepSearch.Tests.csproj -c Release
dotnet build src/RipgrepSearch.Core/RipgrepSearch.Core.csproj -c Release -f net8.0
dotnet build src/RipgrepSearch.Core/RipgrepSearch.Core.csproj -c Release -f net10.0
dotnet run --project tests/RipgrepSearch.Core.Tests/RipgrepSearch.Core.Tests.csproj -c Release -f net8.0
dotnet run --project tests/RipgrepSearch.Core.Tests/RipgrepSearch.Core.Tests.csproj -c Release -f net10.0
```

At the initial extraction, only the .NET 9 SDK was available and could not restore the net10.0 graph: the attempted net10.0 build returned **NETSDK1045**. Normal multi-target restore/build commands require the .NET 10 SDK even though WinForms itself still targets .NET 8. No SDK was installed by the migration task. The subsequent validation below supersedes this initial SDK limitation.

During initial validation, a temporary ignored `obj/migration-net8-only.targets` selected net8.0 only for the two new projects. This did not alter their checked-in target frameworks or the WinForms target. This workaround is unnecessary with the .NET 10 SDK. To reproduce the earlier workaround from the repository root in PowerShell:

```powershell
New-Item -ItemType Directory -Path obj -Force | Out-Null
@'
<Project>
  <PropertyGroup Condition="'$(MSBuildProjectName)' == 'RipgrepSearch.Core' Or '$(MSBuildProjectName)' == 'RipgrepSearch.Core.Tests'">
    <TargetFrameworks>net8.0</TargetFrameworks>
  </PropertyGroup>
</Project>
'@ | Set-Content -LiteralPath obj/migration-net8-only.targets
$net8ValidationTargets = (Resolve-Path obj/migration-net8-only.targets).Path
dotnet build RipgrepSearch.csproj -c Release "-p:DirectoryBuildTargetsPath=$net8ValidationTargets"
dotnet run --project tests/RipgrepSearch.Tests/RipgrepSearch.Tests.csproj -c Release "-p:DirectoryBuildTargetsPath=$net8ValidationTargets"
# Both projects here are multi-targeted, so a direct override is sufficient:
dotnet build src/RipgrepSearch.Core/RipgrepSearch.Core.csproj -c Release -f net8.0 -p:TargetFrameworks=net8.0
dotnet run --project tests/RipgrepSearch.Core.Tests/RipgrepSearch.Core.Tests.csproj -c Release -f net8.0 -p:TargetFrameworks=net8.0
```
